# Test-suite wall clock: design

**Date:** 2026-08-07
**Status:** approved, ready for planning
**Baseline commit:** `828354c9` (clean tree; every measurement below was taken against this exact tree)

## 1. Problem

A full local suite run takes roughly an hour, and sessions sometimes run it more
than once. That wall clock is the dominant cost of a working session.

Suite size, measured by collection:

| Selection | Tests | Files |
|---|---|---|
| default (`-m 'not e2e'`) | 5,104 | 549 |
| `-m e2e` | 845 | 97 |

## 2. What was measured

All e2e timings below use the **same 69 tests** — `test_e2e_tabs.py`,
`test_e2e_fillgate.py`, `test_e2e_guessnumber.py` — at `-n 2`, at `828354c9`.
All 69 passed in every configuration.

| Configuration | Sample (69 tests) | Full e2e, extrapolated |
|---|---|---|
| Windows + local Postgres (today) | 212.8 s / 258.0 s | ~43–53 min |
| Linux container + untuned Postgres | 273.8 s | ~56 min |
| Windows + tuned test Postgres | 136.8 s / 129.2 s | ~27 min |
| Linux container + tuned Postgres | 76.7 s | ~16 min |
| CI today (all 845 e2e tests, `-n 2`) | — | **7 min 47 s** |

Whole CI pipeline, three parallel jobs: **8 min 45 s**, consistently green.

### Findings that shaped the design

1. **Parallelism is exhausted.** The same 69 tests: `-n 2` = 212 s, `-n 8` =
   238 s. More workers is *slower*. Adding cores will not help.
2. **Database creation is not the problem.** Eight test databases, all 78
   migrations: ~20 s total, once per run.
3. **Teardown dominates.** Phase totals across a 28-test sample:

   | phase | Windows | Linux container (untuned) |
   |---|---|---|
   | `call` | 3.07 s | 1.66 s |
   | `setup` | 1.42 s | 0.83 s |
   | `teardown` | 3.30 s | 5.90 s |

4. **The quiescence barrier is innocent.** That run recorded 0 barrier timeouts
   and 0 deadlock retries. `db_quiesce.py` is not the cost.
5. **Root cause: `TRUNCATE … CASCADE` across 89 tables**, run at teardown of
   every test that takes `live_server` — **537 of 630** e2e test functions.
   Timed directly as a single statement:

   | Postgres configuration | `TRUNCATE` of all 89 tables |
   |---|---|
   | default durability | **2,881 ms** |
   | `fsync=off`, `synchronous_commit=off`, `full_page_writes=off`, tmpfs data dir | **78 ms** |

   **37× faster**, with no change to any test.

### A hypothesis that was tested and rejected

The initial theory was that Windows was the root cause, and that moving the
runner to Linux was the fix. That is **wrong**. An untuned Linux container was
the *slowest* configuration measured. The Linux runner is genuinely faster at
real test work (`call` 1.66 s vs 3.07 s; `setup` 0.83 s vs 1.42 s), but that
advantage was swamped by a database durability setting. The database is the
lever; the operating system is a secondary multiplier.

### Measurement caveats, stated deliberately

- **The extrapolation is optimistic.** The 69-test sample over-represents
  `live_server` tests. `test_e2e_math_reflow_dom.py` alone is 171 tests (20% of
  the e2e suite), uses no `live_server`, and pays no truncate. The real
  full-suite win is expected to land **below** the table's ~1.8×. Replacing this
  estimate with a measured number is an explicit deliverable (§5).
- **Local Postgres has ~21% run-to-run variance** (212.8 s vs 258.0 s for
  identical work). The tuned configuration was replicated and is tight
  (136.8 s / 129.2 s).

## 3. Part A — Dedicated tuned test database

### A1. `docker-compose.test.yml`

One service, `libli-test-db`:

- image `postgres:16`
- data directory on **tmpfs**
- command flags `-c fsync=off -c synchronous_commit=off -c full_page_writes=off`
- published on **port 55433**, deliberately not 5432
- `POSTGRES_USER=libli`, `POSTGRES_DB=libli`, `POSTGRES_HOST_AUTH_METHOD=trust`

Two properties matter. The **non-default port** means it cannot be confused with
the instance holding dev and mat-pp data. The **tmpfs** makes it disposable by
construction — a restart wipes it, which is already true of a database pytest
drops and recreates.

`fsync=off` is safe here and only here: the server holds nothing that is not
regenerated by the next run. It must never be applied to the real instance.

### A2. Opt-in wiring in `config/settings/test.py`

```python
_test_db = env("TEST_DATABASE_URL", default=None)
if _test_db:
    DATABASES = {"default": env.db_url_config(_test_db)}
```

This lives in `test.py`, not `base.py`. That placement is the safety property:
no code path lets dev or production point at the throwaway server. When
`TEST_DATABASE_URL` is unset, behaviour is byte-identical to today — a no-op for
anyone who has not started the container.

### A3. Documentation

`.env.example` gains a commented `TEST_DATABASE_URL`. `docs/development/setup.md`
covers starting the service and points at the speed rationale.
`docs/development/conventions.md` records that the test database is disposable
and carries the explicit warning about `fsync=off`.

### A4. The same trick in CI

The `postgres` service in `.github/workflows/ci.yml` gains
`--tmpfs /var/lib/postgresql/data` in `options:`. CI is not the bottleneck, but
the change is nearly free and the e2e job is 7m47s of it.

## 4. Part B — Affected-tests workflow

### B1. Documented practice — `docs/development/testing.md`

- **Locally:** run only affected tests, with per-file justification in the format
  already established by `docs/superpowers/notes/2026-07-28-affected-tests-slice2.md`,
  including its "a red here is a REGRESSION, not migration" classification.
- **Branch gate:** push and let CI's 8m45s be the full-suite gate.
- **Never** run the full suite locally twice in one session.

### B2. `scripts/affected_tests.py`

Advisory, not authoritative. Takes a diff range (default: merge-base with
`master`) and emits candidate test files plus a ready-to-paste pytest command,
split into a unit invocation and a `-m e2e` invocation.

Mapping rules:

| Changed path | Maps to |
|---|---|
| a test file | itself |
| a Python module | tests referencing its import path or its symbols |
| a template / CSS / JS file | tests referencing that filename |
| a migration | transfer and model tests |

The filename rule works unusually well in this repo because many tests assert
against source and template text by name — `test_builder_js_invariants.py`,
`test_editor_scripts.py`, `test_colour_glue_drift.py`.

The script **reports what it could not map**, so gaps are visible rather than
silently dropped. The human still writes the justification; the script removes
the tedium of finding candidates.

### B3. Tests for the helper

Fixture diffs exercising each mapping rule, plus the unmapped-reporting path.

## 5. Verification

1. **One measured full-suite run before and after Part A**, replacing the §2
   extrapolation with a real number. This is a deliverable, not a nice-to-have —
   the estimate is known to be optimistic and should not be left standing.
2. **The suite must stay green.** All 69 sample tests passed under every
   configuration measured; the full run must confirm that at scale.
3. **For `scripts/affected_tests.py`**, per the project's "falsify tests, don't
   run them" rule: each mapping rule gets a named mutant — delete the rule,
   require the corresponding test to go red.

## 6. Non-goals

**The shared-connection teardown rewrite is excluded.** Making `live_server`
share the test's connection so e2e could roll back instead of truncating would
address the same 537 tests, but the 37× truncate win already captures most of
that prize. The rewrite would drive a change through the middle of the
`db_quiesce.py` / `deadlock_retry.py` apparatus — machinery built over several
iterations against a real, measured deadlock — for the remainder. Not worth it.

**Adding xdist workers is excluded**: measured slower (§2, finding 1).

**Moving the runner to Linux is deferred**, not rejected. It is worth a further
~1.7× on top of Part A, but it needs root for Chromium's system libraries and so
cannot be automated unattended. Revisit once Part A's real number is known.

## 7. Risks

| Risk | Mitigation |
|---|---|
| `fsync=off` applied to the real instance | Separate container, non-default port, warning in `conventions.md` |
| tmpfs sized too small for 8 worker databases | Size at 3 GB (measured headroom: test databases are small); document the symptom |
| `affected_tests.py` misses an affected test | Advisory only; CI full suite remains the gate; unmapped paths reported explicitly |
| Developers forget to start the test database | `TEST_DATABASE_URL` unset falls back to today's behaviour — slower, never broken |
